## Finding 1 · A logging bug that breaks Prof. Joshi's item 2

**`agents/answer.py` logs the wrong confidence tier on every single query.**

```python
prompt_variant = "HIGH"
if retrieval.confidence < MEDIUM_CONFIDENCE:
    system_prompt = LOW_CONFIDENCE_DISCLAIMER + ...     # variant never updated
elif retrieval.confidence < HIGH_CONFIDENCE:
    system_prompt = MEDIUM_CONFIDENCE_DISCLAIMER + ...  # variant never updated
```

Measured across all 859 logged queries:

| Actual tier (from the score) | Logged as | Count |
|---|---|---|
| HIGH | HIGH | 490 ✅ |
| **MEDIUM** | **HIGH** | **354** ❌ |
| **LOW** | **HIGH** | **15** ❌ |

**43% of records are wrong.** The disclaimer *was* applied correctly — the user got the right warning. Only the log is wrong.

**Why it matters.** `EVALUATION_PLAN.md` E3 requires **tier separation** — "accuracy within HIGH vs MEDIUM vs LOW" — and calls it "the honest headline". That analysis is impossible from the current logs.

**Recoverable?** Yes. The confidence score is logged, so the tier can be recomputed offline. ₹0.

## Finding 6 · The 70.4% CrPC result is partly caused by my own change

On 23 August I changed the router's fallback from `target_corpus = "BNS"` to **no filter at all**.

- **Before:** criminal queries → BNS only → CrPC would be 0%
- **After:** criminal queries → unfiltered → CrPC 70.4% by base rate

So the number is real, but it measures **the current code**, not the system as it was. It must be reported as *"unfiltered dense retrieval over an unbalanced corpus"*, not as an inherent property.

**And `EVALUATION_PLAN.md` E4 Part B already anticipated this**, with the control I failed to apply:

> *"Report unfiltered retrieval's corpus distribution against corpus volume share, so drift can be separated from genuine relevance. Without this control, 'unfiltered search drifts to CrPC' is unfalsifiable."*

Applying it now:

| | CrPC share |
|---|---|
| Its share of the index (base rate) | **39.1%** |
| Its share of layman retrieval | **70.4%** |

**70.4% against a 39.1% base rate is drift beyond chance — 1.8× over-representation.** With the control, the claim is falsifiable and it survives. Without it, a reviewer would have dismissed it.

## Finding 9 · An undisclosed confound in the confidence ablation

`GAPS.md` #16:

```python
text = re.sub(r'(?m)^\s*(\d+\s?[A-Za-z]?)\s*\.', r'Section \1.', text)
```

This rewrites **any** line starting with a number and a period into `"Section N."` — including page numbers and list items. So a chunk can match `"Section 41"` because page 41 began with `41.`

`GAPS.md` says plainly: *"When you ablate signal 3, this is a confound you must control for or disclose."*

**Signal 3 is `entity_coverage` — the one measured at AUROC 0.492.** Neither `PHASE_G.md` nor `PHASE_H.md` discloses it. It must be added.
